## What is an Inference Engine
*What is an inference engine, why is it needed. Huge catch up phrase for the reader to stay interested.*

A definition I use for inference engines is that they are the orchestration layer of the complete LLM workflow. They handle the memory LLMs need, whether in permanent buffers, such as weights, or “temporary” ones, such as caches. They also handle the compute an LLM performs by orchestrating the execution of all its kernels. Finally, they make it possible to run this workflow for multiple requests concurrently, extracting more performance from these models.


## Why I built MTLQwen?
*Explain what type of inference engine is MTLQwen and what constraints does it have (device, model, memory). What am I looking for by building this? , what can you optimize here that will bring more performance to the table?*

MTLQwen is an inference engine I built specifically for the Qwen 3.5 and 3.8 architectures, focusing on Metal backend for Apple GPUs. It started as a project to learn how inference engines work, but as I went deeper, I realized that specializing it for Qwen and Metal could provide more performance than general-purpose inference engines (vLLM or llama.cpp) on this specific model family and hardware. By using Metal specific features and optimizing Qwen’s kernels, MTLQwen ended up outperforming llama.cpp at both batch size 1 and in aggregate throughput, with a further 30% speedup when using DFlash.
